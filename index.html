WebMCP tools registered by this page

  • describe_current_state — reports every field's value, which required fields are still missing, current status, and available options.
  • list_available_actions — tells the agent exactly what it can do next, given the current state.
  • complete_form_field — fills one field (full_name, email, phone, appointment_type, date, time, notes), validating it and updating the real DOM inputs on screen.
  • confirm_and_submit — checks the form is complete, then stages a review. It cannot finalize the booking itself: finalizing requires a real click on the "Confirm & book appointment" button, which is wired to plain UI code, not to any tool.
  • interpret_intent — the one tool that actually reasons: sends a free-form phrase (e.g. "whenever's soonest for a dental cleaning") to a real LLM via Groq, matched only against this clinic's real current appointment types/dates/open times, then runs whatever it resolves through the exact same validation as complete_form_field. Needs a Groq API key configured below (free tier available). Like complete_form_field, it can only set field values — never stage or finalize a booking.

"Start over" is deliberately not a tool either, for the same reason: an agent can help you fill the form, but only you can throw away your own progress or finalize a booking.

AI interpreter setup (for interpret_intent)

interpret_intent is the only part of this page that makes a network call. It sends your free-form phrase, plus the clinic's currently-available appointment types/dates/times, directly from this browser to Groq's API — using an API key you provide. That key is never bundled with this app, never committed to its repository, and is stored only in this browser's localStorage; nothing else on this page ever sees it. Groq offers a free tier, so trying this tool for real shouldn't cost anything under normal use — but it's still your own account and your own usage. Get a key at console.groq.com/keys.

This calls the exact same functions registered with document.modelContext — useful for testing in any browser, even one without WebMCP support yet. Calls made here appear in the Action log above.

Built as a college project demonstrating WebMCP. No backend of its own — all state lives in this page's memory and resets on reload. The one exception is interpret_intent, which calls Groq's API directly using a key you provide yourself. Tool registration uses document.modelContext.registerTool() per the WebMCP proposal.
